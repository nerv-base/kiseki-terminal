## 1. 参数化单模板 Shader 管线

### 1.1 解决 v1 的四大痛点
在 v1 中，Shader 存在四个工程隐患：
1. 维护爆炸：每个主题若分别手写 `live/eco × glsl/hlsl`，4 个主题就需要维护 16 份代码；
2. 硬编码参数：`BASE_BG`、`BG_OPACITY`、`WINDOW_ALPHA` 写死在 shader 源码内，导致 `termbg` / 透明度覆盖无法与 Live Shader 联动；
3. 未定义行为（UB）：多处 GLSL 存在 `smoothstep(edge0, edge1, x)` 且 `edge0 > edge1`（如 `nerv-eva`、`shinkai-rain`、`kyoto-sakura`）；
4. 窄分屏构图冲突：窗口竖向分屏变窄时，右侧立绘与左侧代码区发生重叠。

### 1.2 单模板 + 编译期宏注入架构
v2 中每个包含动态效果的主题**仅需维护 1 份 `shaders/live.glsl`（Ghostty）和 1 份 `shaders/live.hlsl`（Windows Terminal）**。`kiseki-shader` 在编译生成 `<kiseki_config>/generated/shaders/active.{glsl,hlsl}` 时，自动在文件顶部注入标准化宏头：

```glsl
// === Auto-generated by Kiseki Shader Preprocessor (DO NOT EDIT) ===
#define KISEKI_QUALITY_LEVEL 2         // 0=Static(disabled), 1=Eco, 2=Balanced, 3=Ultra
#define KISEKI_BASE_BG vec3(0.043137, 0.035294, 0.039216)
#define KISEKI_ACCENT_PRIMARY vec3(0.941176, 0.415686, 0.133333)
#define KISEKI_ACCENT_SECONDARY vec3(0.847059, 0.149020, 0.180392)
#define KISEKI_BG_OPACITY 0.7800
#define KISEKI_WINDOW_ALPHA 0.9500
#define KISEKI_SAFE_ZONE_END_X 0.5600
#define KISEKI_NARROW_FADE_ASPECT 1.1500
#define KISEKI_ENABLE_CRT 0            // 1 时启用微弱 CRT 叠加（无需放弃 Live 模式）
// Theme custom params from tokens.json#atmosphere.shader.params
#define KISEKI_PARAM_SCAN_PERIOD_SEC 7.5000
#define KISEKI_PARAM_GLITCH_INTERVAL_SEC 6.0000
// === End Kiseki Header ===
```

**直接收益**：
- **一份模板覆盖 3 个动态档位**：模板内部通过 `#if KISEKI_QUALITY_LEVEL >= 2` 控制粒子层数、循环步数、UV 采样次数，彻底消除 `eco.glsl`/`eco.hlsl` 重复文件。
- **用户参数全链路实时生效**：执行 `kiseki bg 0.55`、`kiseki compose --palette ...` 或 `kiseki crt on` 时，只重算宏头并触发热重载，Live 60fps 与透明度和 CRT 可自由叠加。

## 2. Rendering Profile 渲染档位规范（ADR-010）

| 档位 | `KISEKI_QUALITY_LEVEL` | 行为定义 | 目标场景 |
| :--- | :---: | :--- | :--- |
| **`static`** | `0`（不挂载 Shader） | 纯静态壁纸 + 配色，零额外 GPU 着色器 pass | 极低功耗 / 远程桌面 / 老旧集显 |
| **`eco`** | `1` | 仅保留低开销氛围光晕/缓慢扫描线（单次纹理采样、关闭 UV 扭曲与高循环粒子），大幅降低片元算力 | 笔记本电池续航 / 多分屏编码 |
| **`balanced`（默认）** | `2` | **视觉最大化默认体验**：完整主题核心动画（含 Ghostty 下的 glitch / 水波纹 / 樱瓣 / 流星），结合优化后的 `bgLayerMask` 保护文字 | 日常默认，兼顾视觉冲击力与可读性 |
| **`ultra`** | `3` | 完整多层视差粒子 + 更高密度细节 + 完整光晕采样 | 高性能独显 / 演示录制 |
| **`accessibility`** | `0`（不挂载 Shader） | 关闭壁纸、透明、模糊与一切闪烁/动画；OKLCH 亮度轴自动校准对比度 ≥ WCAG AAA (7.0:1) | 强光环境 / 视觉无障碍 / 高强度阅读 |

### 2.1 Ghostty (`postprocess`) vs Windows Terminal (`layered_background`) 边界说明
- **Windows Terminal (`SHADER_LAYERED_BG`)**：`t0`（文字，空白处 alpha=0）与 `t1`（壁纸）天然分离，所有特效与 UV 扭曲严格作用在 `t1` 背景层，再通过 Porter-Duff Source-Over 合成，100% 不触碰文字像素。
- **Ghostty (`SHADER_POSTPROCESS`)**：输入为已合成的单张 `iChannel0`。按 ADR-010，`Balanced` 档位默认保留完整视觉特效（含 glitch 与水波纹），但必须强制遵守以下三条编码规范以最大化保护可读性：
  1. **统一提供 `kiseki_bg_mask(vec4 term, vec2 uv)` 标准库片段**（由预处理器注入），结合 `KISEKI_BASE_BG`、色差、亮度与 `KISEKI_SAFE_ZONE_END_X` 计算文字保护权重；
  2. **所有反向 `smoothstep` 全面禁止**：一律改写为 `1.0 - smoothstep(lo, hi, x)`（严格保证 `lo < hi`）；
  3. **窄分屏长宽比自适应淡出**：统一提供 `kiseki_narrow_factor(vec2 res)`：
     ```glsl
     float kiseki_narrow_factor(vec2 res) {
         float aspect = res.x / max(res.y, 1.0);
         // 宽屏返回 1.0；窄分屏（aspect < KISEKI_NARROW_FADE_ASPECT）平滑衰减至 0.0
         return smoothstep(0.65, KISEKI_NARROW_FADE_ASPECT, aspect);
     }
     ```
     当窗口被拆成窄分屏时，右侧立绘光效与 glitch/波纹自动淡出归零，零常驻进程解决窄窗口文字遮挡问题。

## 3. 内嵌 `naga` 静态校验与复杂度预算（防 UB 与防 GPU 挂起）

得益于 Rust 单栈（ADR-002），`kiseki-shader` 直接将 **`naga`**（`wgpu` 官方着色器前端与 IR 校验器）静态编入二进制，无需用户安装 `glslangValidator` 或 DirectX SDK，在 `kiseki theme validate`、`kiseki theme install` 及 `kiseki doctor` 中自动执行四道门禁：

### 门禁 1：语法与语义解析（GLSL / HLSL）
- 对注入标准宿主页眉（Ghostty ShaderToy 风格 `iResolution`/`iTime`/`iChannel0` 包装壳；WT `PixelShaderSettings` cbuffer + `t0`/`t1`/`s0` 包装壳）后的完整源码调用 `naga::front::glsl`（以及 HLSL 解析器/CI `dxc` 双校验）。
- 任何未定义标识符、类型不匹配、非法隐式转换直接拒绝。

### 门禁 2：GLSL/HLSL 未定义行为（UB）静态扫描
在解析前后的 AST / Naga IR 上执行强制规则：
- **禁止反向 `smoothstep(a, b, x)`**：当常量 `a >= b` 时报错并自动提示改写为 `1.0 - smoothstep(b, a, x)`。
- **禁止潜在除零**：检查裸 `term.rgb / term.a`，要求使用 `max(term.a, 0.001)`。
- **禁止危险扩展与非片元特性**：禁止 `#extension` 启用计算着色器/原子操作/外部存储写入。

### 门禁 3：防 GPU 驱动挂起（TDR）复杂度预算
恶意或劣质 Shader 的超大循环可直接触发 Windows TDR / macOS GPU Reset，导致终端甚至桌面卡死。`kiseki-shader` 遍历 Naga IR 强制校验静态预算上限：

| 指标 | `eco` 上限 | `balanced` / `ultra` 上限 | 说明 |
| :--- | :---: | :---: | :--- |
| Shader 源码大小 | ≤ 32 KB | ≤ 64 KB | 防止巨型生成代码 |
| 静态纹理采样次数（`texture` / `Sample`） | ≤ 4 次 | ≤ 16 次 | 控制显存带宽与采样延迟 |
| 循环嵌套深度 | ≤ 1 层 | ≤ 2 层 | 禁止深层嵌套循环 |
| 单循环必须为常量上界且迭代次数 | ≤ 8 次 | ≤ 32 次 | **禁止 `while(true)` 或运行期不可判定上界的循环** |
| 动态分支（非均匀控制流） | 限制 | 静态告警 | 辅助性能评估 |

### 门禁 4：多平台 CI 真机/编译校验
- CI 在 Linux/macOS/Windows Runner 上额外用 `glslangValidator` + `dxc`（DXIL SM 5.0/6.0）交叉编译所有官方与社区 PR 提交的 Shader，确保零驱动兼容问题。

## 4. 零代码执行安全沙箱（ADR-012）

> **核心安全假设**：任何外部安装或从未来 Gallery 拉取的主题包，均被视为**不可信输入（Untrusted Input）**。安装或切换主题**绝不能**以任何途径触发任意命令执行（RCE）、越权文件读写或宿主配置破坏。

### 4.1 攻击面与强制防御矩阵

| 攻击向量 | 风险说明 | v2 强制防御措施 |
| :--- | :--- | :--- |
| **Prompt RCE** | Oh My Posh `command` segment、Starship `[custom.*]` 可在每次回车执行任意 Shell 命令 | 主题包**禁止**携带原始 `prompt.omp.json` 或 `starship.toml`；仅允许在 `tokens.json#overrides.prompt` 中填写受 JSON Schema 白名单校验的纯视觉字段，由 Core 内置安全模板编译器生成最终 Prompt 配置 |
| **脚本/Lua 覆盖 RCE** | WezTerm `wezterm.lua`、Neovim `init.lua`、Shell hook 脚本本身是图灵完备代码 | 主题包中**严禁包含** `.lua`、`.sh`、`.zsh`、`.ps1`、`.vim`、`.py`、`.exe`、`.dylib`、`.so` 等一切可执行/脚本后缀文件；解包校验阶段见即拒绝 |
| **Config Injection（配置注入）** | 恶意颜色或标签字符串注入 `\ncommand = evil` 到 `ghostty.conf`/`kitty.conf` 或 `$(evil)` 到 `env.zsh` | 1) JSON Schema 强正则约束（颜色仅 `#RRGGBB`，标签禁止换行/反引号/`$`/`;`/`\|`/`&`/`<`/`>`/控制字符）<br>2) `kiseki-compiler` 渲染每个输出格式时再做一次目标格式专用转义（Shell 单引号安全转义、TOML/JSON 序列化器输出、Key-Value 禁止换行） |
| **Zip Slip / 符号链接穿越** | 恶意压缩包包含 `../../.ssh/authorized_keys` 或指向敏感路径的 symlink | 解包前强制校验每个归档条目的规范化路径必须严格位于目标沙箱目录内；**直接拒绝包含 symlink / hardlink / device 节点的主题压缩包**；限制解压后总大小（默认 ≤ 30MB）与文件数（≤ 64）防 Zip Bomb |
| **Shader GPU DoS (TDR)** | 百万次死循环卡死 GPU 驱动，导致终端打不开 | 1) 安装前强制过内嵌 `naga` 静态循环上界与纹理采样预算校验<br>2) 提供 `kiseki recover --safe` 紧急救援命令 |
| **供应链篡改 / 降级攻击** | 自更新或字体/主题下载被劫持，或 Stable 回退到未审计 `main` 分支 | 1) 强制 HTTPS + SHA256 校验（未来加 minisign/Cosign 签名）<br>2) **严禁任何路径从 tagged release 回退到 `main` 分支** |

### 4.2 主题包允许文件扩展名白名单
解包器仅放行以下扩展名（其余一律直接拒绝安装）：
- 元数据与文档：`.json`（仅限根目录 `manifest.json`、`tokens.json`）、`LICENSE`、`CREDITS.md`
- 静态图像：`.png`、`.jpg`、`.jpeg`、`.webp`（安装时用纯 Rust 图像头解析验证真实魔数与分辨率上限 ≤ 8192×8192）
- 纯文本徽章：`.txt`（仅限 `assets/logo.txt`，校验大小 ≤ 32KB，仅允许 UTF-8 文本与安全 SGR 颜色转义 `\x1b[...m`，**禁止 OSC / DCS / CSI 终端控制命令注入**，防御终端标题/剪贴板/窗口控制攻击！）
- 着色器模板：`.glsl`、`.hlsl`（必须通过 `naga` 校验与预算门禁）

## 5. 主题包与资源版权 / 字体授权规范（ADR-014）

面向长期社区维护与未来 Kiseki Gallery 上线，从第一版即确立清晰法务与版权基线：

1. **引擎与官方代码许可**：Kiseki Core 源码采用 **MIT License**。
2. **主题包强制作者与来源声明**：
   - 每个主题包根目录必须包含 `LICENSE`（SPDX 标识与正文一致）与 `CREDITS.md`。
   - `manifest.json#provenance` 必须显式声明 `wallpaperOrigin`（`original | cc0 | cc-by | licensed | none`）与 `shaderOrigin`，说明壁纸/美术资产的合法再分发权；Gallery PR 自动化审核将拒绝缺失 provenance 或含未经授权商业版权素材的投稿，并保留 DMCA/下架响应流程。
3. **字体严格解耦（严禁包内再分发）**：
   - 任何主题包（含官方与第三方）**严禁打包 `.ttf`/`.otf`/`.woff2` 字体文件**。
   - 主题在 `L4 Typography` 中仅声明字体族名或标准 Font Catalog ID；需要下载时，由 `kiseki fonts install` 从内置校验清单（`font-catalog.json`，仅收录具备明确免费再分发许可如 SIL OFL-1.1 / MIT / Apache-2.0 的上游官方 Release 直链 + SHA256）直接拉取安装。
4. **官方 4 个旗舰主题资产审计**：
   - 在 `v2.0` 发布前，对 `starlight-8bit`、`nerv-eva`、`shinkai-rain`、`kyoto-sakura` 的壁纸、Shader、Logo 逐一补齐 `LICENSE` 与 `CREDITS.md` 声明，作为社区主题包的黄金范本。
